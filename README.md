# Конфигурационное управление. Практическая работа №2

Вариант 25. Инструмент для анализа и визуализации зависимостей Python-пакетов.

## Текущее состояние

Реализованы первые четыре этапа: проверка настроек, получение зависимостей, построение транзитивного графа рекурсивным BFS и поиск обратных зависимостей.

Поддерживаются максимальная глубина, фильтрация пакетов, циклические зависимости и работа с тестовым JSON-файлом.

Граф включает все объявленные зависимости, в том числе условные и дополнительные. Для корневого пакета используется указанная пользователем версия, для транзитивных пакетов — последние версии из репозитория. Ограничения совместимости версий и условия окружения не применяются.

Обратные зависимости находятся разворотом ребер и повторным использованием того же BFS. В тестовом режиме рассматривается весь файл репозитория. Для реальных пакетов поиск выполняется внутри графа, построенного от `--package` с заданной глубиной и фильтром.

## Требования

Python 3.10 или новее.

Используется стандартная библиотека Python. Сборка и установка дополнительных библиотек не требуются.


## Запуск

Команды выполняются из основной папки проекта.

```sh
python3 -m src.main --package requests --version 2.32.3 --max-depth 1
```

Пример вывода:

```text
Граф зависимостей requests==2.32.3:
requests: charset-normalizer, idna, urllib3, certifi, pysocks, chardet
charset-normalizer: -
idna: -
urllib3: -
certifi: -
pysocks: -
chardet: -
```
Знак `-` означает отсутствие исходящих ребер в построенном графе. На границе заданной глубины дальнейшие зависимости не запрашиваются.

## Параметры

| Параметр | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `--package` | Имя анализируемого пакета | Обязательный |
| `--version` | Версия пакета | Обязательный |
| `--repository` | Базовый URL репозитория или путь к тестовому файлу | `https://pypi.org/pypi` |
| `--test-mode` | Включение режима тестового репозитория | Выключен |
| `--ascii` | Запрос вывода зависимостей в виде ASCII-дерева | Выключен |
| `--max-depth` | Максимальная глубина анализа: целое число от 0 до 100 | `3` |
| `--filter` | Подстрока для исключения пакетов из анализа | Пустая строка |
| `--reverse PACKAGE` | Поиск обратных зависимостей указанного пакета | Не задан |

После `--reverse` указывается имя пакета. Например, `--reverse D` ищет пакеты, которые зависят от D.

Флаги `--test-mode` и `--ascii` указываются без значения.

В тестовом режиме имя пакета должно состоять из заглавных латинских букв, а `--repository` должен указывать на существующий файл.

Глубина `0` оставляет только корневой пакет, глубина `1` включает прямые зависимости. Фильтр исключает пакеты, содержащие указанную подстроку, без учета регистра. Исключенные пакеты не обходятся.

В тестовом режиме граф читается из JSON-файла. Циклические связи сохраняются, но уже обнаруженные пакеты повторно не обходятся.

Вывод ASCII-дерева пока не реализован и относится к пятому этапу.

## Примеры использования

Обратные зависимости пакета D:

```sh
sh run.sh --package A --version 1 --test-mode --repository examples/repository.json --reverse D --max-depth 4
```

Только прямые потребители пакета D:

```sh
sh run.sh --package A --version 1 --test-mode --repository examples/repository.json --reverse D --max-depth 1
```

Пакет без обратных зависимостей:

```sh
sh run.sh --package A --version 1 --test-mode --repository examples/repository.json --reverse F
```

Обычный обход, включая цикл:

```sh
sh run.sh --package A --version 1 --test-mode --repository examples/repository.json
```

Ограничение глубины:

```sh
sh run.sh --package A --version 1 --test-mode --repository examples/repository.json --max-depth 1
```

Исключение пакета B:

```sh
sh run.sh --package A --version 1 --test-mode --repository examples/repository.json --filter B
```

Указать глубину и фильтр:

```sh
python3 -m src.main --package requests --version 2.32.3 --max-depth 2 --filter urllib
```

Включить настройку ASCII-дерева:

```sh
python3 -m src.main --package requests --version 2.32.3 --ascii
```

Проверить обработку ошибочной глубины:

```sh
python3 -m src.main --package requests --version 2.32.3 --max-depth -1
```

При успешном выполнении программа завершается с кодом `0`. При ошибке выполнения - с кодом `1`. При ошибке параметров командной строки - с кодом `2`.

## Функции программы

Файл `src/repository.py`:

- `get_dependencies` запрашивает зависимости указанной версии пакета, а при `version=None` — последней версии.
- `extract_dependencies` извлекает список зависимостей из ответа репозитория.

Файл `src/config.py`:

- `package_name` проверяет допустимые символы в имени пакета.
- `version_string` проверяет формат строки версии.
- `depth_value` проверяет, что глубина является целым числом в допустимых пределах.
- `filter_string` проверяет строку фильтра.
- `build_parser` описывает параметры командной строки и значения по умолчанию.
- `validate_url` проверяет адрес репозитория.
- `validate_repository` выбирает проверку URL или тестового файла.
- `parse_args` читает параметры командной строки и запускает их проверку.

Файл `src/graph.py`:

- `normalize_name` приводит имя Python-пакета к единой форме.
- `validate_test_repository` проверяет описание тестового графа.
- `load_test_repository` читает и проверяет JSON-файл.
- `package_dependencies` получает имена прямых зависимостей из файла или репозитория.
- `bfs_recursive` обходит граф по уровням с помощью рекурсии.
- `build_graph` строит граф с учетом глубины, фильтра и режима.
- `reverse_repository` разворачивает направление всех ребер графа.
- `build_reverse_graph` строит граф обратных зависимостей тем же рекурсивным BFS.

Файл `src/main.py`:

- `main` выбирает прямой или обратный обход и выводит результат или сообщение об ошибке.

## Тестирование

Запуск тестов:

```sh
python3 -m unittest discover -s tests -v
```

Проверяются:

- - Значения всех семи настроек по умолчанию.
- Изменение настроек пользователем.
- Обработка неправильных значений параметров.
- Ошибка при отсутствии обязательных параметров.
- Извлечение списка зависимостей из ответа репозитория.
- Обработка ответа без зависимостей.
- Обработка некорректного ответа репозитория.
- Построение графа с циклом и общей зависимостью.
- Ограничение глубины.
- Фильтрация пакетов, включая корневой пакет.
- Обработка отдельного и неизвестного пакета.
- Проверка полноты описания тестового репозитория.
- Разворот направления ребер.
- Поиск прямых и косвенных обратных зависимостей.
- Применение глубины и фильтра при обратном обходе.
- Обработка пакета без обратных зависимостей и неизвестного пакета.

При успешном выполнении в конце выводятся `Ran 21 tests` и `OK`.
